# PharmaStock — Production deployment (MongoDB Atlas + Render + Vercel)

| Layer | Where | Exposure |
|---|---|---|
| Frontend (Vite/React) | Vercel (`frontend/`, see `frontend/vercel.json`) | Public |
| API Gateway `pharmastock-gateway` :5000 | Render web service (Docker) | **Public — the only public backend** |
| `pharmastock-auth` :5002, `pharmastock-medicine` :5003, `pharmastock-inventory` :5004, `pharmastock-notification` :5005, `pharmastock-sales` :5006, `pharmastock-purchase` :5007, `pharmastock-reporting` :5008 | Render private services (Docker) | Private network only |
| MongoDB (`pharmastock` database) | MongoDB Atlas | Not hosted on Render |

The backend is described by the Blueprint [`render.yaml`](render.yaml). Local development
(`docker compose`) is unchanged and does not use this file.

## Rules that always apply

- **Never reset, drop or delete MongoDB data.** No `dropDatabase`, no `mongorestore --drop`,
  no re-seeding a production database. `dev-seed` is refused in production unless
  `ALLOW_SEED=true`; never set it on Render.
- **Never use `docker compose down -v`** (it deletes the local MongoDB volume) — not for local
  work and not as part of any production migration.
- **Only the Gateway is public.** The 7 services are `pserv` (private) and must stay private;
  `/internal/*` routes are never proxied by the Gateway.
- **`JWT_SECRET` is identical on every backend service.** It lives in the `pharmastock-shared`
  environment group (generated once by Render). Never set a per-service override.
- **`INTERNAL_API_TOKEN` is shared by inventory, notification, sales and purchase.** It lives in
  the `pharmastock-internal` environment group (generated once by Render). Inventory rejects
  internal calls whose `x-internal-token` does not match.
- **Notification runs with exactly one instance** (`numInstances: 1`): it hosts the periodic
  stock/expiration check. Do not scale it horizontally or enable autoscaling on it.
- No secret is committed. Secrets are generated by Render or typed into the Render Dashboard.
  Do not create production `.env` files.

## How the private service URLs are built

The services validate full URLs (`AUTH_SERVICE_URL=http://host:5002`, …), but Render private
hostnames carry a generated suffix (for example `pharmastock-auth-ab12`) and Blueprints cannot
interpolate values. Each consumer therefore receives the provider host through
`fromService … property: host` (`AUTH_PRIVATE_HOST`, `INVENTORY_PRIVATE_HOST`, …), and its
`dockerCommand` composes the URLs with the fixed ports before starting the image's normal entry
point:

```
/bin/sh -c export AUTH_SERVICE_URL=http://$AUTH_PRIVATE_HOST:5002 && exec node dist/server.js
```

| Variable built at start | Services |
|---|---|
| `AUTH_URL`, `MEDICINE_URL`, `INVENTORY_URL`, `NOTIFICATION_URL`, `SALES_URL`, `PURCHASE_URL`, `REPORTING_URL` | gateway |
| `AUTH_SERVICE_URL` | medicine, inventory, notification, sales, purchase, reporting |
| `MEDICINE_SERVICE_URL` | inventory, sales, purchase |
| `INVENTORY_SERVICE_URL` | notification, sales, purchase |

These URL variables therefore do not appear in the Dashboard; the `*_PRIVATE_HOST` ones do.
Check the result with `GET https://<gateway>.onrender.com/gateway/health`: it lists every URL
the Gateway uses and the status of each service.

## Values entered in Render

Prompted once when the Blueprint is created (`sync: false`, per service). Later edits in the
Dashboard are kept across Blueprint syncs; **newly added** `sync: false` keys are not prompted
again and must be added manually in the Dashboard.

| Key | Services | Value |
|---|---|---|
| `MONGODB_URI` | all 7 private services | Atlas URI **including** `/pharmastock`, e.g. `mongodb+srv://<user>:<password>@<cluster>.mongodb.net/pharmastock?retryWrites=true&w=majority` |
| `CLIENT_URL` | all 7 private services | Final frontend origin, e.g. `https://<project>.vercel.app` (must be a valid URL; no trailing slash) |
| `CORS_ORIGINS` | all 7 private services | Optional extra origins, comma-separated (e.g. a custom domain). May be left empty |
| `ALLOW_PUBLIC_REGISTER` | auth | `true` only until the first ADMIN exists, then `false` |

Generated by Render (never typed, never copied into files): `JWT_SECRET`,
`INTERNAL_API_TOKEN`.

Fixed in `render.yaml`: `NODE_ENV=production`, `JWT_EXPIRES_IN=7d`, `PORT` per service,
`EXPIRATION_WARNING_DAYS=30` (inventory, notification, reporting),
`STOCK_CHECK_ENABLED=true` and `STOCK_CHECK_INTERVAL_MS=3600000` (notification),
`SERVICE_TIMEOUT_MS=10000` (sales, purchase).

Plans: private services have no free plan on Render; all services use `0.5c-512mb` (adjust in
`render.yaml` if needed). Region: `frankfurt` for every service (the private network requires a
single region, and the region cannot be changed later). Change it in `render.yaml` **before**
the first deployment if your Atlas cluster is elsewhere.

---

## 1. MongoDB Atlas

1. Create (or reuse) a cluster, ideally in the same geographic region as Render (`frankfurt` →
   AWS `eu-central-1`).
2. **Database Access**: create a user with `readWrite` on the `pharmastock` database.
   Optionally create a second user with `read` only, for `pharmastock-reporting`.
3. **Network Access**: allow Render's outbound traffic. Either add `0.0.0.0/0` (simplest, relies
   on strong credentials) or the outbound IP ranges listed on each Render service's
   *Connect → Outbound* tab after creation.
4. Copy the `mongodb+srv://` connection string and add `/pharmastock` before the `?`.
   URL-encode special characters in the password.
5. If existing data must be moved to Atlas, use `mongodump` / `mongorestore` **without**
   `--drop`, into the `pharmastock` database. Never empty the target database.

## 2. Render environment and secrets

1. Push the repository (with `render.yaml`) to GitHub; connect GitHub to Render.
2. Render Dashboard → **New → Blueprint** → select the repository and branch `master`.
3. Render shows the 8 services and the environment groups `pharmastock-shared` and
   `pharmastock-internal` (`JWT_SECRET` and `INTERNAL_API_TOKEN` are generated automatically).
4. Fill the prompted values (table above) for each service:
   - `MONGODB_URI`: the Atlas URI from step 1.
   - `CLIENT_URL`: the Vercel URL you intend to use (e.g. `https://pharmastock.vercel.app`). If it
     is not known yet, enter a valid placeholder such as `https://example.vercel.app` and fix it
     in step 12.
   - `CORS_ORIGINS`: empty, or extra origins.
   - `ALLOW_PUBLIC_REGISTER` (auth): `true`.
5. Click **Apply**. Render creates all services together; the order below is the order in which to
   check them (each service needs the ones listed before it to be fully functional).

For each service, open **Logs** and confirm the server started and connected to MongoDB.
A wrong/missing variable makes the service exit at startup with an explicit message.

## 3. Deploy Auth — `pharmastock-auth`
No dependency on other services. Expect the startup log on port 5002 and a MongoDB connection.

## 4. Deploy Medicine — `pharmastock-medicine`
Needs Auth (`AUTH_SERVICE_URL`). Port 5003.

## 5. Deploy Inventory — `pharmastock-inventory`
Needs Auth and Medicine; verifies `INTERNAL_API_TOKEN`. Port 5004. Atlas is a replica set, so
multi-document transactions are used.

## 6. Deploy Notification — `pharmastock-notification`
Needs Auth and Inventory; sends `INTERNAL_API_TOKEN`. Port 5005. One instance only. The stock
check runs every hour (`STOCK_CHECK_INTERVAL_MS=3600000`).

## 7. Deploy Sales — `pharmastock-sales`
Needs Auth, Medicine and Inventory; sends `INTERNAL_API_TOKEN`. Port 5006.

## 8. Deploy Purchase — `pharmastock-purchase`
Needs Auth, Medicine and Inventory; sends `INTERNAL_API_TOKEN`. Port 5007.

## 9. Deploy Reporting — `pharmastock-reporting`
Needs Auth. Port 5008. Read-only (no writes, no index creation). You may set its `MONGODB_URI`
to the read-only Atlas user.

## 10. Deploy the Gateway — `pharmastock-gateway`
Public web service, port 5000, health check `/gateway/health`.

```powershell
Invoke-RestMethod https://<gateway>.onrender.com/gateway/health | ConvertTo-Json -Depth 5
Invoke-RestMethod https://<gateway>.onrender.com/api/health | ConvertTo-Json -Depth 5
```

`/gateway/health` must list `http://pharmastock-<name>-xxxx:<port>` URLs and report every
service as up; `/api/health` reports the database as connected only if all services are.
Note the Gateway public URL, e.g. `https://pharmastock-gateway.onrender.com`.

## 11. Deploy the frontend on Vercel

1. Vercel → **Add New Project** → import the repository.
2. **Root Directory**: `frontend` (framework, install/build commands and SPA rewrite come from
   `frontend/vercel.json`).
3. Environment variable (Production): `VITE_API_URL=https://<gateway>.onrender.com/api`.
   It is read at **build** time: redeploy the frontend whenever it changes.
4. Deploy and note the final domain (e.g. `https://pharmastock.vercel.app`).

## 12. Update `CLIENT_URL` / `CORS_ORIGINS` with the final Vercel domain

CORS is enforced by each service (exact origin match, no trailing slash). In Render, for **each
of the 7 private services**, set:

- `CLIENT_URL=https://<final-vercel-domain>`
- `CORS_ORIGINS=` any additional origins (custom domain, …), comma-separated, or empty.

Save → **Save, rebuild and deploy** (or Manual Deploy) for each service. Check in the browser
console that API calls from the Vercel site are no longer blocked by CORS.

## 13. Bootstrap the first ADMIN

Registration always creates an `EMPLOYEE`.

1. With `ALLOW_PUBLIC_REGISTER=true`, register the administrator account from the frontend
   (`/register`).
2. In Atlas (**Browse Collections** → `pharmastock.users`, or `mongosh`), change **only that
   user's** role:
   ```js
   db.users.updateOne({ email: "admin@your-pharmacy.example" }, { $set: { role: "ADMIN" } })
   ```
   Do not modify any other document.
3. Log out and log in again (the frontend caches the user profile; the API reads the role from
   the database on each request) and confirm admin pages are available.

## 14. Disable `ALLOW_PUBLIC_REGISTER`

Render → `pharmastock-auth` → Environment → `ALLOW_PUBLIC_REGISTER=false` → save and redeploy.
From now on only an authenticated ADMIN can create accounts. Verify:

```powershell
try { Invoke-RestMethod -Method Post -ContentType 'application/json' `
  -Uri https://<gateway>.onrender.com/api/auth/register `
  -Body '{"firstName":"x","lastName":"x","email":"x@example.com","password":"Password123!"}' } catch { $_.Exception.Response.StatusCode }
```

Expect `Unauthorized` (401), not a created account.

## 15. Smoke test

On the Vercel site, as the ADMIN:

1. Log in / log out / log in again.
2. Dashboard loads (reporting).
3. Create a category, a medicine and a supplier.
4. Create a purchase and receive it → a batch appears and stock increases.
5. Create a sale → stock decreases (FEFO), and the sale detail is correct.
6. Stock movements and batches pages show the operations.
7. Notifications/alerts page loads (low stock / expiration once the hourly check has run).
8. Reports page and audit logs load.
9. `GET /gateway/health` still shows every service up.

## Notes

- Free Render web services spin down when idle; the Gateway uses a paid plan in `render.yaml`
  to avoid cold starts and to stay on the private network reliably.
- Rate limiting runs per service behind the Gateway; clients reaching the services through the
  proxy may share limits. Review before heavy production traffic.
- Responses generated by the Gateway itself (e.g. 502 when a service is down) carry no CORS
  headers; the browser reports them as CORS errors. Check `/gateway/health` in that case.
- Changing `JWT_SECRET` logs out every user; changing `INTERNAL_API_TOKEN` requires a redeploy
  of the 4 services that use it.
